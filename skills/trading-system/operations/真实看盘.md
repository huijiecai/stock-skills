## 二、快扫+深析（命令差异）

### 2.1 快扫（连续运行，信号检测）

```
□ 一键4步快扫（机械·1次Bash调用）
  ./scripts/op_scan_live.sh <持仓codes>
  脚本内部合并：①指数 ②持仓 ③全主板无方向异动候选 ④板块强度
  → 指数异动？持仓是否触发§4.1？是否有高影响力先导候选？concept方向/涨停方向？

□ 无信号 → 不写日志，立即下一次快扫（连续扫描不等待；heartbeat每5分钟记一行）
□ 有信号 → 立即进入深析
  - 持仓涨跌>2% → 持仓巡检
  - CANDIDATE → 先查主营/催化完成方向归因；禁止直接称龙头或直接买入
  - ②板块强度发现强势方向 或 方向内涨停 或 ≥3只核心股>5% → 买入评估（优先于持仓巡检）
  方向不在state.md §四 → Mode A（含WebSearch）
```

> **禁止直接执行 astock 命令**。快扫必须通过 `./scripts/op_scan_live.sh` 完成。
> 脚本保证：①持仓只输出判断结果 ②全主板异动扫描报告实际覆盖数/缺失报价/候选 ③板块输出结构化concept/style/涨停方向 ④候选明确标为CANDIDATE，不会提前输出“龙头”

快扫预算：1次Bash调用（op_scan_live.sh） · ≤100 token · ~15-20秒

> **heartbeat格式**（无信号时每5分钟记一行）：
>
> | 轮次 | 时间 | 指数趋势 | 异动候选 | 板块方向 | 涨停方向 | 信号 |
> |------|------|---------|---------|---------|------|
>
> - 指数趋势：上证/深证/科创50涨跌幅
> - 异动候选：新增CANDIDATE代码+异动类型；无新增写“无”
> - 板块方向：concept前3方向+涨跌幅
> - 涨停方向：涨停板块名+数量
> - 信号：无信号·heartbeat / ②方向走强→③深析
> - **禁止**：持仓价格不独立成列（①是判断题，已评估→秒过；§4"不设价格止损，预期依据仍在验证→持有，无论价格涨跌"）

### 2.2 深析（命令差异）

深析流程（思考步骤）→ `看盘公共规范.md §二`。以下为真实看盘命令：

```
□ op_sector_members — 看板块领涨股
  astock live block members <板块代码>

□ market_candidate_attribution — 无方向异动归因
  → 搜索候选为什么上涨：公告/新闻/财经媒体/雪球等
  → 找到具体预期，并据此列出关联股票
  → astock live quote <关联股票>：检查核心关联股是否成片同步上涨
  → 成片上涨=归因成立；只有候选上涨=继续搜索/孤立异动不交易
  → 已结束方向仍从零Mode A

□ op_multi_snapshot — 资金广度
  python3 scripts/op_direction_live.py <pool_id>
  # 进入买入评估前只看可执行主板成员
  python3 scripts/op_direction_live.py <pool_id> --mainboard-only

□ op_stock_minute — 价格深度
  astock live minute <龙头候选>
  → 对所有龙头候选逐只查询，不止查一只

□ leader — 归因成立后确认龙头
  → 固定五步：记录首次异动时间→读取注册固定池全量报价→对所有候选逐只查询分钟路径→比较启动顺序/涨速/成交主动性/持续性→输出“先导/方向龙头/跟随”
  → 关联股票中最先发动、涨幅最强、成交最主动且承接最好的才是龙头
  → 龙头不可买只进入第二/第三名执行检查，不得删除龙头身份

□ op_holdings — 看持仓当前状态（卖出方向）
  ./scripts/op_holdings_live.sh <持仓codes>

□ op_sector_members — 看持仓所在板块表现（卖出方向）
  astock live block members <板块代码>

□ op_multi_snapshot — 看预期相关个股表现（卖出方向）
  python3 scripts/op_direction_live.py <pool_id>
```

深析预算：≤5次工具调用 · ≤500 token · 2-4分钟

> **深析脚本说明**：op_holdings 已有实时脚本（op_holdings_live.sh）。其余深析命令（op_sector_members / op_multi_snapshot / op_stock_minute）暂用 astock 直接执行，后续逐步脚本化。

## 三、Token管理

- 主对话只保留：当前轮摘要（≤200字）+ 待执行预案 + 关键决策结论
- 禁止保留：完整live block rank输出、多轮quote历史、八维扫描结果
- token 60% → 主动启动状态更新
- token 70% → 收尾退出，提示新开session

## 四、事件驱动留证

AI是在持续判断，不是定时打卡。有价值的变化才停下来做完整留证。

### 必须留证事件

| 触发类型 | 具体情形 | 产出文件 | 时机 |
|---------|---------|---------|------|
| 拟执行买卖 | 三维齐+锁定三件事+账户级排序/双出口卖出检查 | HHMM_买卖_标的_思考链路.md | 日内实时 |
| 持仓异动 | 日内振幅>5%或触发§4.1评估 | HHMM_持仓异动_标的.md | 日内实时 |
| 预期阶段切换 | 持仓方向阶段变化 | HHMM_预期切换_方向.md | 日内实时 |
| 盘中新方向 | 盘前预案外方向走强且联动 | HHMM_新方向_方向.md | 日内实时 |
| 无方向异动 | 高影响力主板候选触发并完成归因 | HHMM_异动归因_标的.md | 日内实时 |
| 关键锚点异动 | 产业数据破位/龙头炸板/政策突发 | HHMM_锚点异动_事件.md | 日内实时 |

以上留证均为日内实时产出。收盘更新checklist A项用于检查日内是否有遗漏。
