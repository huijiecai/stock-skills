# 模拟看盘操作手册

> **定位**：收盘后的分钟级持续模拟，用历史数据训练决策能力。公共规则（轮转池/深析流程/决策落盘/执行链/市场节点/trades格式/state.md格式/轮末自检）→ `operations/看盘公共规范.md`，本文件只定义模拟看盘独有部分。
> 系统知识引用：核心框架.md（判断）、买卖规则.md（决策）、数据验证.md（数据）
> 数据源：astock历史数据 → operations/数据验证.md

---

## 一、定位与边界

- 本文件 = 分钟级模拟机制（怎么转）+ 模拟看盘独有部分
- 公共规则 → `operations/看盘公共规范.md`
- 触发任何买卖决策 → 索引买卖规则.md，不在此重复

### 与真实看盘的区别

| 维度 | 模拟看盘 | 真实看盘 |
|------|---------|---------|
| 触发 | 收盘后启动 | "开始看盘"启动循环 |
| 数据源 | astock query（历史·预先拉取） | astock live（实时TDX） |
| 决策 | 写入模拟看盘.md + 思考链路文件 | AI自主拍板执行（虚拟账户） |

**核心原则**：模拟看盘 = 真实看盘。唯一区别是数据源——先拉取历史分钟数据，再逐分钟模拟推进。机制、规则、决策流程完全相同。

## 二、启动序列

```
□ 读取 data/state.md → 加载持仓+现金+预期追踪
□ 读取 data/daily/YYYY-MM/DD-盘前分析.md → 提取今日催化清单+预案（含方向内核心股清单）
□ 读取 system/核心框架.md → 加载判断框架
□ 读取 system/买卖规则.md → 加载决策规则
□ 数据同步（详见 数据验证.md §二 模拟看盘数据同步）：
  - 4大指数分钟K线（op_index.sh依赖）
  - 全部板块日K（op_sector_rank依赖）
  - 板块排名前50：astock query block rank <date> --limit 50（快扫②板块强度依赖）
  - 涨停清单：astock query limit <date>（快扫②板块强度依赖）
  - 涨停股分钟K线：astock sync kline --code <涨停codes> --freq 1m（快扫②板块强度依赖·判断每只涨停股封板时间点）
  - 持仓股分钟K线（op_holdings.sh依赖）
  - 全部股票日K（涨停判定依赖）
  - 盘前预案方向内核心股分钟K线（方向强度检测依赖）
```

## 三、快扫+深析（命令差异）

### 3.1 快扫（逐分钟推进，信号检测）

从09:30开始，逐分钟推进至15:00。每分钟执行四个机械取数（对应看盘公共规范.md §一 6类轮转池①②）：

```
□ op_index — 看指数（机械）
  op_index.sh <date> <HH:MM>
  → 指数异动？→ 信号

□ op_holdings — 看持仓（①持仓巡检·机械）
  op_holdings.sh <持仓codes> <date> <HH:MM>
  → 持仓涨跌幅>2%？是否触发卖出规则§4.1评估？→ 信号

□ op_sector_rank — 看板块强度（②板块强度·机械）
  → 启动时已拉取板块排名前50 + 涨停清单 + 涨停股分钟K线
  → 当前时间点：涨停股中哪些已封板？（查分钟K线确认封板时间）
  → 按方向/板块归类涨停股
  → 板块排名前50中，哪些方向有涨停？哪些方向≥3只个股>5%？
  → 某方向出现涨停 → 该方向在state.md §四吗？
    · 在§四 → 三维确认完成？→ 是→买入评估 / 否→继续观察
    · 不在§四 → 执行Mode A（→ 预期研究.md §二）
  → 某方向≥3只个股涨幅>5%但未涨停 → 集体走强 → 同上

□ 方向强度检测 — 用分钟K线检查②发现的强势方向 + 预案方向内核心股
  astock query kline <方向内核心股> --freq 1m --date <date>
  → 当前时间点：哪些核心股涨停了？哪些集体走强（≥3只>5%）？
  → 与②板块强度交叉验证

□ 无信号 → 推进到下一分钟
□ 有信号 → 立即进入深析（→ 看盘公共规范.md §二）
  - 持仓涨跌>2% → 持仓巡检
  - ②板块强度发现强势方向 或 方向内涨停 或 ≥3只核心股>5% → 买入评估（优先于持仓巡检）
  方向不在state.md §四 → Mode A（含WebSearch）
```

快扫是逐分钟推进的持续检测，有信号才停下来做完整分析。
②发现强势方向 → 立即同轮触发深析，不等下一轮（→ 看盘公共规范.md §一）。

### 3.2 深析（命令差异）

深析流程（思考步骤）→ `看盘公共规范.md §二`。以下为模拟看盘命令：

```
□ op_sector_members — 看板块领涨股
  astock query block members <板块代码> <date>

□ op_multi_snapshot — 资金广度
  先同步分钟K线：astock sync kline --code <codes> --freq 1m
  op_multi_snapshot.sh <方向内标的> <date> <HH:MM>

□ op_stock_minute — 价格深度
  astock query kline <龙头候选> --freq 1m --date <date>
  → 对所有龙头候选逐只查询，不止查一只

□ op_holdings — 看持仓当前状态（卖出方向）
  op_holdings.sh <持仓codes> <date> <HH:MM>

□ op_sector_members — 看持仓所在板块表现（卖出方向）
  astock query block members <板块代码> <date>

□ op_multi_snapshot — 看预期相关个股表现（卖出方向）
  （若未同步则先 astock sync kline --code <codes> --freq 1m）
  op_multi_snapshot.sh <方向内标的> <date> <HH:MM>
```

深析完成后 → 返回快扫（推进到下一分钟）

## 四、交易后更新state.md+trades.md

看盘公共规范.md §二执行链中的"更新state.md+trades.md"具体要求：

**state.md**：
- §一持仓表 → 更新对应标的的数量/买入价/当前价/浮盈（买入新增或修改行，卖出修改数量或删除行）
- §二账户 → 现金（±交易金额）、总资产（现金+全部持仓市值）、今日盈亏

**trades.md**：格式 → `看盘公共规范.md §五`

收盘时额外更新：state.md当前价→收盘价、浮盈重算。

## 五、收盘评估与复盘

### 5.1 预期对照

- 预期确认/兑现/失效了吗？对照盘前判断 vs 实际
- 盘中感知准确度：哪些信号提前预示了预期变化？
- 覆盖诊断：今天有没有在加速期才发现某个方向？→ 追问为什么盘前没扫到

### 5.2 复盘交易

每笔交易回顾：预期是什么？确认/兑现/失效了吗？决策合规吗？

### 5.3 更新预期阶段

核心框架.md §3.1，标注各方向阶段变化

### 5.4 更新state.md §一§二

虚拟账户：持仓+现金+总资产

### 5.5 合规检查

- [ ] 每笔交易是否对照了三维确认？
- [ ] 买入前是否锁定了三件事？
- [ ] 卖出是否基于预期逻辑而非价格？
- [ ] 是否遗漏了盘中感知的新方向？
- [ ] 复盘标准：赚钱违规=错误 / 亏钱合规=正确
- [ ] 三维齐→必须执行？
- [ ] 买卖决策是否写了思考链路文件？

## 六、收盘更新checklist

```
## 收盘更新checklist
- [ ] A. 持仓异动验证（日内振幅>5%的持仓是否已留证）
- [ ] B. 逐股扫描：涨停全部过一遍（逐只归因→方向→是否新方向）
- [ ] C. 逐股扫描：炸板全部过一遍（为什么炸？方向还有效？）
- [ ] D. 逐股扫描：成交额前50（异动检测→是否隐含新预期）
- [ ] E. 预期研究模式B更新全部方向（每日必做，→ operations/预期研究.md）
- [ ] F. state.md §四更新（阶段/价格/今日变化）
- [ ] G. state.md §一§二 + trades.md（→ 看盘公共规范.md §五）
- [ ] H. lessons.md（如有新教训）
- [ ] I. 收盘总结
- [ ] J. 看盘文件存档
```

逐股扫描 → `看盘公共规范.md §七`。

## 七、输出

写入 `data/daily/YYYY-MM/DD-模拟看盘.md`，内容包括：
- 分钟级持续模拟日志（有信号的分钟才记录，无信号的不写）
- 买卖决策明细（引用思考链路文件）
- 持仓+账户更新
- 复盘与合规检查
- 覆盖诊断结论

思考链路文件写入 `data/daily/YYYY-MM/HHMM_动作_标的_思考链路.md`。
