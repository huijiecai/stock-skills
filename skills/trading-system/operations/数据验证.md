# 数据验证与astock操作指南

> **边界**：本文件定义数据获取的规范和操作方法。
> 行情数据是交易决策的基础设施，所有数据必须经astock验证，禁止凭记忆/印象。

---

## 一、核心原则

- **astock是唯一行情数据入口** — 所有行情数据（报价/K线/涨停/板块/指数）必须通过astock获取
- **禁止凭记忆引用数据** — 任何行情数据必须实时拉取验证，不能用"上次看到是..."
- **WebSearch只用于消息面** — 政策/公告/研报/外盘消息，禁止用WebSearch替代行情查询
- **禁止curl直读数据库** — 不直连ClickHouse/PostgreSQL

---

## 二、看盘原子操作

看盘过程中的机械取数固化为 `scripts/` 下的脚本和命令，AI直接调用获取数据，自行完成思考判断。脚本需从项目根目录运行。

### 操作清单

| # | 操作 | 看什么 | 真实看盘 | 模拟看盘 |
|---|------|--------|---------|---------|
| 1 | op_index | 上证/深证/科创/创业板涨跌幅 | `./scripts/op_index_live.sh` | `./scripts/op_index.sh <date> <HH:MM>` |
| 2 | op_sector_rank | 板块涨幅排名前50 | `astock live block rank --limit 50` | `astock query block rank <YYYYMMDD> --limit 50` |
| 3 | op_holdings | 持仓当前报价+涨跌幅 | `astock live quote <codes>` | `./scripts/op_holdings.sh <codes> <date> <HH:MM>` |
| 4 | op_sector_members | 板块内领涨股 | `astock live block members <block_code>` | `astock query block members <block_code> <YYYYMMDD>` |
| 5 | op_multi_snapshot | 多股快照（三维确认用） | `astock live quote <codes>` | `./scripts/op_multi_snapshot.sh <codes> <date> <HH:MM>` |
| 6 | op_stock_minute | 个股分钟K线详情 | `astock live minute <code>` | `astock query kline <code> --freq 1m --date <YYYYMMDD>` |
| 7 | op_limit_list | 涨停明细 | （盘中从live推导） | `astock query limit <YYYYMMDD> --exclude-st` |
| 8 | op_market_candidates | 全主板无方向异动候选 | `astock live market --json` | `replay_minute_signals.py --date <YYYYMMDD>` |

### 用法示例

```bash
# === 真实看盘 ===
./scripts/op_index_live.sh                              # 指数概览（实时）
astock live block rank --limit 50                        # 板块排名前50
astock live quote 002185 600584                          # 持仓快照
astock live block members 880672                         # 板块领涨股
astock live quote 002185 600584 002156 600206 603986     # 多股快照
astock live minute 002185                                # 个股分时

# === 模拟看盘 ===
./scripts/op_index.sh 20260709 10:04                     # 指数概览
./scripts/op_holdings.sh 002185,600584 20260709 10:04    # 持仓快照
./scripts/op_multi_snapshot.sh 002185,600584,002156 20260709 10:04  # 多股快照
astock query block rank 20260709 --limit 50              # 板块排名
astock query block members 880672 20260709               # 板块领涨股
astock query kline 002185 --freq 1m --date 20260709      # 个股分时
astock query limit 20260709 --exclude-st                 # 涨停明细
astock live market --json                                # 全主板快照+异动候选（候选不是龙头）
```

### 模拟看盘数据同步

脚本使用 `--no-sync` 避免同步消息污染JSON输出，未同步的数据会返回"无数据"。

**启动前同步**（快扫依赖）：

```bash
# 1. 4大指数分钟K线（op_index.sh依赖）
astock sync kline --code 000001,399001,000688,399006 --type index --freq 1m

# 2. 全部板块日K（op_sector_rank依赖）
astock sync kline --type block --freq daily --all

# 3. 持仓股分钟K线（op_holdings.sh依赖）
astock sync kline --code 002185,600584 --freq 1m

# 4. 全部股票日K（涨停判定/板块排名依赖）
astock sync kline --type stock --freq daily --all
```

**深析阶段动态同步**（信号触发后）：

```bash
# 确定要看的方向内标的/板块领涨股，先同步再取数
astock sync kline --code 002156,600206,603986 --freq 1m
./scripts/op_multi_snapshot.sh 002156,600206,603986 20260709 10:04
```

真实看盘无需同步，live命令实时拉取。

### 其他常用命令

```bash
astock query market                        # 市场概览（涨跌家数/成交额/板别）
astock query meta --keyword 600487         # 股票代码搜索/验证
astock query limit ladder                  # 连板天梯
astock query kline 000630 --limit 30       # 日K线（非看盘场景）
```

**验证同步状态**：`astock stats` 或 `astock query kline <code> --limit 1`，确认最新日期。

## 三、强制验证（引用数据前必做）

| 验证类型 | 何时执行 | 方法 | 典型错误 |
|---------|---------|------|---------|
| **代码验证** | 查询个股前 | `query meta` / WebSearch | 中船特气688626(错)→688146(对)→涨跌全反 |
| **同步验证** | 查询特定日期前 | `stats` 或 `kline --limit 1` | 用6/18数据当6/22→黄河旋风+5.34%(实际涨停) |
| **涨停验证** | 引用涨停数时 | `query limit YYYYMMDD` | 磷概念12涨停(实际4) |
| **K线验证** | 引用涨跌/连板时 | `query kline <code>` | 直接采信consecutive_days |

## 四、分析准确性五步法

做方向分析时，必须按以下顺序思考：

1. **预期是什么** — 必须说出具体催化（涨价/政策/业绩），不能是"这个板块在涨"
2. **资金在炒什么** — WebSearch + astock验证，禁止直接采信概念标签
3. **个股归因** — 每只涨停股追问"实际催化是什么？"，每只只归入一个方向（主驱动）
   - 搜索公告、新闻、财经媒体、雪球等信息，找出市场正在交易的具体预期
   - `industry/sector/business`和概念标签只用于帮助搜索，不能直接代替上涨原因
   - 根据预期列出关联股票；核心关联股成片同步上涨，才说明归因正确、预期得到资金确认
   - 归因最小输出：具体事件→最短传导链→直接受益池→联动结论；池先于行情建立
   - 涨价事件必须标明产品、直接销售者、销量受益者、相邻题材和成本受压者
   - 只有异动股自己上涨：继续搜索；仍无合理解释则作为孤立异动，不交易
   - 归因确认后，关联股票中最先发动、涨幅最强、成交最主动的是龙头
4. **龙头确认** — 归因成立后，在关联股票中比较谁最先发动、涨幅最强、成交最主动
5. **标的列表按产业链排序** — 直接受益→相关→不相关。禁止从涨停清单倒推标的

### 覆盖验证（强制）

- 真实看盘：`live market`必须报告`universe/scanned/missing_quotes/failed_batches`；覆盖不足必须显式标记。
- 方向固定池：必须从 `data/research/pools.json` 读取，并用 `python3 scripts/op_direction_live.py <pool_id>` 报告注册数量、返回数量和缺失代码；禁止使用临时手写池替代。池内 `300/301/688` 只能用于研究联动，买入前必须使用 `--mainboard-only`，且候选代码必须是 `000/001/002/003/600/601/603/605`。
- 账户审计：`python3 scripts/audit_account.py` 默认读取 `state.md` 的持仓收盘价；任何持仓缺价必须显式传入 `--close CODE=PRICE`，否则审计失败，禁止用旧价或零值静默补齐。
- 信号查重：卖出/买入动作必须在 `data/signal_ledger.json` 取得唯一 signal ID；相同日期、方向和证据指纹再次注册应失败。
- 模拟看盘：必须报告`COVERAGE_MODE/SCANNED_SYMBOLS/MISSING_CANDIDATES/SCANNED_MINUTES`。
- 只有分钟数没有股票数，不构成“全市场逐分钟扫描”证明。
- `candidate_universe`模式禁止表述为全市场覆盖；盘中冲高回落且未进入候选池的股票属于明确数据缺口。

## 五、典型错误与注意事项

### 数据错误案例

| 错误类型 | 具体表现 | 后果 |
|---------|---------|------|
| 数据未同步 | 用6/18数据当6/22 | 黄河旋风+5.34%（实际涨停+9.99%） |
| 代码错误 | 中船特气688626(错)→688146(对) | 涨跌全反 |
| 涨停数凭记忆 | 磷概念12涨停 | 实际只有4只 |
| 概念标签直接归因 | 氟概念10涨停 | 实际只有3只 |

### 违反五步法的典型表现

- 多氟多挂"氟概念"→归入电子特气，但实际驱动是六氟磷酸锂（锂电池）
- 磷化工归因为磷矿石涨价，实际是磷酸铁锂价格翻倍
- 和远气体/康强电子/百合花不是电子特气却列入标的
- 中船特气（正宗龙头）不在标的列表中

### 注意事项

- **连板数据必须K线逐日验证** — `consecutive_days`是区间涨停总天数，不是连续天数
- **龙虎榜是滞后数据** — 盘后披露，不参与当日盘中判断，仅作次日参考
- **astock缺命令/字段 → 补到astock里** — 不要绕开工具自建查询
