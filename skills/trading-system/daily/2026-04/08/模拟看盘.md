## 二、原版模拟看盘的错误诊断

### 错误1：没做盘前分析

**结果**：开盘前不知道要盯什么方向，没有预设"盘中新方向关注条件"。

**系统规则违反**：第三节"每日流程·盘前"要求"全市场催化扫描"和"预设盘中新方向关注条件"。

**影响**：没有盘前预案=没有基准线=盘中不知道该看什么。

### 错误2：没有执行盘中感知

**结果**：10:30通用设备3只涨停、10:38元件方向5只涨停，完全没有触发快速评估流程。

**系统规则违反**：第四节"三个触发条件"——"意料外的板块异动（某方向2-3只以上涨停，且该方向不在盘前预案中）"应触发快速评估。

**影响**：盘中出现大量可做方向（元件7涨停、通用设备10涨停、贵金属6涨停），但全部被忽略。

### 错误3：三维确认被错误排除

**结果**：写了"外部事件驱动的普涨不属于三维确认范畴"。

**事实**：元件/PCB方向的三维确认完全满足——CCL涨价是产业预期（不是外部事件），板块联动7只涨停是资金确认，多只封板是价格确认。

**系统规则违反**：2.1节"预期不问出处，确认只看资金"。

### 错误4：盯盘标的太固定

**结果**：从头到尾只看4/7盘前预案的9只标的，没有扫描全市场。

**系统规则违反**：盘中感知的目的就是"发现预案没覆盖到的东西"。

### 错误5：模拟看盘模板导致思维惯性

**这是根本原因**——详见下方第三节分析。

## 三、模拟看盘模板问题分析

### 当前模板结构（从之前几天的文件提取）

```
一、监控标的分时数据
二、盘前清单验证（对照盘前预案的标的）
三、盘中感知（记录异动但不主动扫描）
四、虚拟账户操作
五、模拟总结
六、数据快照
七、虚拟账户状态
```

### 问题诊断

**问题1："监控标的"是封闭的，不是开放的**

当前模板的"监控标的"来自盘前预案，一旦写入就固定了。盘中发现的新方向没有入口加入监控列表。

→ **缺少"新增监控标的"机制**：盘中感知触发后，应该立即将新方向的核心标的加入监控，后续时间点跟踪它的走势。

**问题2："盘中感知"是被动记录，不是主动扫描**

当前模板的"盘中感知"是写完其他部分后"补记"的，不是在模拟流程中主动触发的。实际思维路径是：

```
错误路径：盯老标的 → 老标的不行 → 空仓 → 最后补写盘中感知
正确路径：盯老标的 → 老标的不行 → 扫描全市场 → 发现新方向 → 评估 → 操作
```

→ **缺少"全市场扫描"强制步骤**：模板应该在10:00、10:30、11:00、13:00、14:00各设一个"全市场扫描"检查点，强制回答"有没有不在监控列表里的方向在异动？"

**问题3："虚拟账户操作"在"盘中感知"之后**

决策流程应该是：盘中感知→评估→操作→记录。但模板把操作放在感知后面，导致思维上"先决定不操作，再补写为什么没操作"。

→ **顺序应该调整**：盘中感知（含全市场扫描）→ 快速评估 → 买入决策 → 虚拟账户操作

**问题4：缺少"增量资金确认"检查点**

今天是典型的增量资金行情（1.61万亿→2.43万亿），但模板没有强制检查"成交额预估是否显著增加"。成交额变化是感知增量资金的最直接信号。

→ **缺少"成交额预估"环节**：应该在10:00（第一小时成交额×4=全天预估）和13:30（半天实际成交额×2=全天预估）各做一次成交额预估。

**问题5：模拟看盘是盘后写的，容易后视镜**

模板没有强制标注"盘中视角 vs 后视镜"。盘中感知应该是"当时只能看到那个时间点之前的数据"，但盘后写的时候很容易用全天结果来"验证"判断。

→ **缺少"时间隔离"机制**：每个时间段的判断只能基于该时间点之前的数据，后续数据用标记区分。

### 修正后的模板结构

```
零、盘前确认（即使没做盘前分析，也必须回溯记录开盘前已知信息）
一、全市场扫描（强制！10:00/10:30/11:00/13:00/14:00各一次）
  - 涨停方向分布（截至该时间点）
```

## 六、新增教训

**L041：模拟看盘的"监控标的"必须包含"盘中新增"——不能只盯盘前标的，全市场扫描是强制步骤**

**L042：三维确认的预期依据不问出处——停火带来的增量资金进入CCL涨价方向，三维确认同样满足。不要用"外部事件"作为不操作的借口**

**L043：涨停首封时间分布是判断方向的工具——10:00-11:00集中首封=增量资金在开盘兑现后开始建仓，这是盘中感知的最佳触发窗口**

**L044：盘中感知不是"盘后补记"，是模拟流程中的强制步骤——10:00/10:30/11:00/13:00/14:00各做一次全市场扫描**

**删除**：L039（"外部事件驱动的普涨不属于三维确认范畴"）——这条教训本身是错的，三维确认只看信号是否满足
