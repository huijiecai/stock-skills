# 交易系统 v2 架构设计

> 设计日期：2026-06-22
> 基于 v1（trading-system/）近3个月实战迭代经验
> 状态：**已实施**

---

## 一、v1 结构性问题诊断

### 1.1 核心问题：单体文件膨胀 + 跨文件重复

| 问题 | 具体表现 | 影响 |
|------|---------|------|
| trading-system.md 737行 | 同时承担世界观+判断框架+买卖规则+执行流程+数据指南5种职责 | AI每次加载需消化全文，定位效率低 |
| SKILL.md 与 trading-system.md 大量重复 | SKILL.md的§三红线规则(~100行)是trading-system.md§五的精简副本 | 每次规则迭代需同步两处，易遗漏 |
| §五纪律红线与§1-§2决策章节重复 | R1-R11的约束在决策层已完整说明，红线章节用"禁止"语气再说一遍 | 同一规则出现2-3次，歧义风险 |
| §三+§四+§七碎片化 | 每日流程、盘中异动、执行纪律分3个章节，实际是同一件事 | 执行时需跨章节拼接 |
| 缺astock操作指南 | R12/R13混在红线章节里，实际是数据操作指南 | AI找不到独立的工具使用说明 |

### 1.2 设计原则（v2 必须满足）

1. **每个核心概念只出现一次**——在它的归属文件中
2. **买卖规则内嵌约束**——不在后置章节重复定义红线
3. **文件按能力边界拆分**——AI按需加载，不全量读取
4. **SKILL.md只做索引**——不复制规则细节
5. **新增数据验证指南**——独立的astock操作手册
6. **系统/操作/参考/数据四层分离**——系统知识被引用，操作流程被执行，模板按需加载，数据按生命周期组织

### 2.1 四层架构

```
系统层（system/）—— 独立自洽的知识库，仅被引用
  ├── 核心框架.md    "什么是预期？怎么看？"
  ├── 买卖规则.md    "满足什么条件买/卖？买多少？"
  └── 数据验证.md    "怎么用astock拿准确数据？"

操作层（operations/）—— 可执行工作流，遇到决策时索引系统层
  ├── 盘前分析.md    "催化扫描 → 方向评估 → 预案 → 深度研究"
  ├── 模拟看盘.md    "五阶段回放 → 决策训练 → 复盘"
  └── 真实看盘.md    "快扫+深析循环 → 决策落盘 → 归档"

参考层（reference/）—— 输出格式模板，写文件时按需加载
  ├── 每日文档模板.md        "盘前/看盘/复盘文档格式"
  ├── 行业分析模板.md      "产业链分析输出格式"
  └── 公司分析模板.md      "公司分析输出格式"

数据层（data/）—— 系统运行时产生的数据，按生命周期组织
  ├── state.md          "我现在在哪？"（持仓+现金+预期+运行状态，高频读写）
  ├── daily/            "今天做了什么？"（每日日志，只增不改）
  ├── research/         "我研究过什么？"（产业链+公司，长期有效）
  └── lessons.md        "我学到了什么？"（教训候补区，毕业后进system/）
```

**调用关系**：
```
操作层文件  ─遇到买卖决策→  买卖规则.md
           ─遇到预期判断→  核心框架.md
           ─遇到数据需求→  数据验证.md（astock）
           ─遇到消息面需求→ WebSearch / xueqiu
           ─写输出文档→   reference/模板
           ─读写状态→    data/state.md（买卖后更新、决策前读取）
           ─写日志→      data/daily/（盘前/看盘/复盘）
           ─写教训→      data/lessons.md（复盘时）
```

### 3.2 核心框架.md（世界观+判断，~120行）

> **边界原则**：本文件只定义“是什么”和“怎么判断”，不定义“什么时候做”和“怎么做”。
> 盘前怎么发现预期 → operations/盘前分析.md。盘中怎么感知异动 → operations/真实看盘.md。

```
# 核心框架：预期驱动交易体系

## 一、什么是预期
  1.1 定义：预期 = 市场资金正在投票的产业方向/事件催化
  1.2 核心逻辑：确认=买，兑现/失效=卖
  1.3 系统原则：不猜、不赌、不扛；低频但确定

## 二、预期的来源与判断
  2.1 预期从哪来：产业催化、政策事件、资金异动
  2.2 预期依据四类
      - 产业驱动（涨价/缺货/扩产/技术突破）
      - 成长逻辑（业绩拐点/渗透率提升/份额扩张）
      - 政策催化（产业政策/补贴/监管变化）
      - 个股事件（重组/回购/业绩预告）
  2.3 确认的含义：有资金投票 + 有价格响应 + 有可验证依据

## 三、预期生命周期
  3.1 五阶段模型
      | 阶段 | 含义 | 判断标准 | 系统含义 |
  3.2 分歧 ≠ 结束
      - 判断方法：预期依据还在被验证→分歧；被否定→结束
      - 实战案例
  3.3 预期类型识别
      | 类型 | 退出信号特征 | 案例 |
      （持续数据型/事件节点型/实时感知型）

## 四、感知信号解读
  4.1 信号 = 提醒注意，不是触发条件
  4.2 各信号解读指引
      - 涨停数/封板率/跌停数
      - 换手率
      - 成交额
      - 连板高度/晋级率
      - 产业数据指标
  4.3 倒计时催化效应
  4.4 关键原则
      - 概念标签 ≠ 归因结论
      - 大叙事反向拆解（≥20涨停时）
      - 连板股独立归因
```

### 3.3 买卖规则.md（决策+约束，~250行）

```
# 买卖规则

## 一、买入门槛
  1.1 前提一：市场存在可验证的新预期
      - 新叙事/新催化/新可验证点
      - 违反=系统性错误
  1.2 前提二：三维确认（资金+价格+预期依据）
      - 三维：资金确认 + 价格确认 + 预期依据（→核心框架.md §2.2-2.3）
      - 缺一=不买
      - 具体检查方法 → operations/（盘前分析.md §三 / 真实看盘.md §二）
  1.3 前提三：锁定三件事
      - 预期是什么 / 兑现标志 / 失效标志
      - 买前锁定，买后不改
      - 未定义=不执行

## 二、买入执行
  2.1 买点类型与仓位
      | 类型 | 时机 | 仓位 | 判断方法 |
      （确认3成/首板1-1.5成/回调加到3成）
  2.2 龙头识别
      - 领涨性+主动性+高位性
      - 大盘共振是更强确认
      - 龙头买不进=不参与
  2.3 执行时机
      - 确认在哪发生就在哪买
      - 竞价/盘中/涨停排板/一字板（放弃）
  2.4 系统确认=必须行动（反向红线）
      - 三维齐+有窗口+退出清晰 → 必须执行
      - 违反=同等严重
  2.5 信息不足=默认不操作
      - 信息不足指维度数据缺失，不是没找到完美数据
      - 三维数据均可获取=信息充足，必须行动

## 三、持仓管理
  3.1 建仓与加减仓
  3.2 龙头切换：回归原始预期（不问龙头换没换）
  3.3 卖出后新信号：重新评估，不是追悔

## 四、卖出规则
  4.1 纯预期止损（不设价格止损）
  4.2 兑现信号 → 走
      - 利好公告/数据见顶/充分定价/逻辑讲完
  4.3 失效信号 → 立即走
      - 新题材吸血/龙头A杀/联动消失/依据被推翻/数据破位
  4.4 卖出判断三步流程
      Step1: 兑现/结束？→ 卖
      Step2: 失效信号？→ 卖
      Step3: 资金确认还在？→ 减仓或持有
  4.5 常见错误
      - 把分歧当失效
      - 盘前红线脱离买入预期
      - 不因大盘打折仓位
  4.6 不机械执行
  4.7 盘中感知 ≠ 追涨

## 五、组合规则
  5.1 同主题不叠仓（最多3成）
  5.2 多主题并发（各自独立3成）
  5.3 产业链相关性约束（同链总仓位>6成不加仓）
  5.4 单主题只做龙头

## 六、执行纪律
  6.1 系统说买就买，说卖就卖
  6.2 不在确认买点上犹豫
  6.3 复盘标准：合规 ≠ 赚钱（赚钱违规=错误/亏钱合规=正确）
  6.4 系统迭代流程（仅盘后）
      - 触发：盘后复盘发现规则漏洞/歧义/过时
      - 步骤：定位根因 → 修改对应系统文件 → 验证无连带影响 → 记录到data/lessons.md
      - 禁止盘中改系统
```

### 3.4 数据验证.md（astock操作指南，~100行）

```
# 数据验证与astock操作指南

## 一、核心原则
  - astock是唯一行情数据入口
  - 所有数据必须经astock验证，禁止凭记忆/印象

## 二、四类强制验证
  | 类型 | 何时执行 | astock命令 | 典型错误 |
  | 代码验证 | 查询个股前 | query meta / WebSearch | 中船特气688626→688146 |
  | 同步验证 | 查询特定日期前 | stats 或 kline --limit 1 | 用6/18数据当6/22 |
  | 涨停验证 | 引用涨停数时 | query limit YYYYMMDD | 磷概念12涨停(实际4) |
  | K线验证 | 引用涨跌/连板时 | query kline <code> | 直接采信consecutive_days |

## 三、分析准确性五步法
  3.1 预期是什么（必须说出具体催化）
  3.2 资金在炒什么（WebSearch/astock验证，禁止直接采信概念标签）
  3.3 个股归因（每只涨停股追问实际催化，每只只归入一个方向）
  3.4 正宗龙头验证（龙头不响应=方向不达标）
  3.5 标的列表按产业链排序（直接受益→相关→不相关，禁止从涨停清单倒推）

## 四、常用命令速查
  ### 数据同步
  astock sync all --all --days 1 --skip-info --skip-finance --skip-xdxr --skip-minute
  astock sync all --code 600487,002463 --days 1 --skip-info --skip-finance --skip-xdxr
  astock sync kline --code 603893 --freq 1m --days 1

  ### 实时查询（直连TDX）
  astock live quote 600519                     # 个股报价
  astock live minute 600519                    # 分时数据
  astock live block rank --type concept --limit 30  # 概念排名
  astock live block members <板块代码> --json    # 板块成分股

  ### 历史查询（ClickHouse）
  astock query kline 000630 --date YYYYMMDD --limit 30
  astock query kline 600487 --freq 1m --date YYYYMMDD --limit 240
  astock query limit YYYYMMDD --exclude-st
  astock query limit ladder                    # 连板天梯
  astock query block rank --date YYYYMMDD --type concept --limit 30
  astock query market                          # 三大指数/涨跌停/成交额
  astock query meta                            # 股票代码搜索

  ### 实时监控
  watch -n 300 './astock live quote 002407 002463 ...'

## 五、典型错误案例
  ### 6/22教训（4类错误集中爆发）
  ① 数据未同步→用6/18数据当6/22→黄河旋风+5.34%(实际涨停+9.99%)
  ② 代码错误→中船特气688626(错)→688146(对)→涨跌全反
  ③ 涨停数凭记忆→磷概念12涨停(实际4)
  ④ 概念标签直接归因→氟概念10涨停(实际3)

  ### 违反分析五步法的典型表现
  ① 多氟多挂氟概念→归入电子特气，但实际驱动是六氟磷酸锂(锂电池)
  ② 磷化工归因为磷矿石涨价，实际是磷酸铁锂价格翻倍
  ③ 和远气体/康强电子/百合花不是电子特气却列入标的
  ④ 中船特气（正宗龙头）不在标的列表中
```
