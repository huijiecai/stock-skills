# 模拟看盘操作手册

> **定位**：收盘后的分钟级持续模拟，用历史数据训练决策能力。
> 系统知识引用：核心框架.md（判断）、买卖规则.md（决策）、数据验证.md（数据）
> 数据源：astock历史数据 → operations/数据验证.md

---

## 一、定位与边界

- 本文件 = 分钟级模拟机制（怎么转）+ 落盘规范
- 买卖规则.md = 决策规则（买不买、卖不卖）
- 核心框架.md = 判断体系（预期怎么看）
- 触发任何买卖决策 → 索引买卖规则.md，不在此重复

### 与真实看盘的区别

| 维度 | 模拟看盘 | 真实看盘 |
|------|---------|---------|
| 触发 | 收盘后启动 | "开始看盘"启动循环 |
| 数据源 | astock query（历史·预先拉取） | astock live（实时TDX） |
| 视角 | 严格盘中（不用收盘后信息） | 严格盘中 |
| 决策 | 写入模拟看盘.md + 思考链路文件 | AI自主拍板执行（虚拟账户） |
| 机制 | 快扫+深析分钟级持续循环 | 快扫+深析持续循环 |

**核心原则**：模拟看盘 = 真实看盘。唯一区别是数据源——先拉取历史分钟数据，再逐分钟模拟推进。机制、规则、决策流程完全相同。

## 二、启动序列

```
□ 读取 data/state.md → 加载持仓+现金+预期追踪
□ 读取 data/daily/YYYY-MM/DD-盘前分析.md → 提取今日催化清单+预案
□ 读取 system/核心框架.md → 加载判断框架
□ 读取 system/买卖规则.md → 加载决策规则
□ 数据同步（详见 数据验证.md §二 模拟看盘数据同步）：
  - 4大指数分钟K线（op_index.sh依赖）
  - 全部板块日K（op_sector_rank依赖）
  - 持仓股分钟K线（op_holdings.sh依赖）
  - 全部股票日K（涨停判定依赖）
□ 预拉取今日参考数据：
  - op_limit_list → 涨停明细（含概念标签）
  - op_sector_rank → 概念排名前50（收盘参考）
□ 将概念排名与盘前催化清单交叉核对
```

## 三、快扫+深析分层执行

### 3.1 快扫（逐分钟推进，信号检测）

从09:30开始，逐分钟推进至15:00。每分钟执行三个机械取数：

```
□ op_index — 看指数（机械）
  op_index.sh <date> <HH:MM>
  → 指数异动？→ 信号

□ op_holdings — 看持仓（机械）
  op_holdings.sh <持仓codes> <date> <HH:MM>
  → 持仓涨跌幅>2%？触及止损/止盈？→ 信号

□ 板块强度参考（从启动预拉取的收盘排名看）
  概念排名中哪个方向靠前？已有涨停是什么方向？
  → 信号

□ 无信号 → 推进到下一分钟
□ 有信号 → 立即进入深析
```

快扫是逐分钟推进的持续检测，有信号才停下来做完整分析。

### 3.2 深析（信号触发，完整分析）

#### 买入方向

```
□ 思考：板块为什么强？
  对照盘前分析，预期确定了吗？还是新方向？
□ op_sector_members — 看板块领涨股（机械）
  astock query block members <板块代码> <date>
  → 领涨个股是哪些？
□ 思考：领涨的是预期内核心个股吗？
  是 → 继续
  不是 → 第一天？主升期？重新分析预期？
□ op_multi_snapshot — 资金广度（机械）
  先同步分钟K线：astock sync kline --code <codes> --freq 1m
  op_multi_snapshot.sh <方向内标的> <date> <HH:MM>
  → 多只同步走强？
□ op_stock_minute — 价格深度（机械）
  astock query kline <龙头> --freq 1m --date <date>
  → 放量突破？
□ 思考：三维确认
  资金广度✓ + 价格深度✓ + 预期依据✓？
  → 买卖规则.md §1.2 + 盘前分析.md §3.4
□ 三维齐 → 写思考链路 → 买入评估（买卖规则.md §二）
  三维不齐 → 记录放弃理由 → 返回快扫
```

#### 卖出方向

```
□ op_holdings — 看持仓当前状态（机械）
  op_holdings.sh <持仓codes> <date> <HH:MM>
□ op_sector_members — 看持仓所在板块表现（机械）
  astock query block members <板块代码> <date>
  → 板块还在走强吗？
□ op_multi_snapshot — 看预期相关个股表现（机械）
  op_multi_snapshot.sh <方向内标的> <date> <HH:MM>
  → 同方向其他标的走势如何？
□ 思考：预期是否兑现或失效？
  兑现 → 卖出评估（买卖规则.md §4.4）
  失效 → 卖出评估（买卖规则.md §4.4）
  还在确认中 → 持有
```

### 3.3 信号触发即深析

快扫检测到信号 → 立即进入深析。有信号才停，无信号持续推进。

## 四、6类轮转池

| # | 关注点 | 层级 | 数据动作 | 思考输出 |
|---|--------|------|---------|---------|
| ① | 持仓巡检 | 快扫 | op_holdings | 涨跌幅>2%？触及止损/止盈？ |
| ② | 板块强度 | 快扫 | op_limit_list + op_sector_rank | 方向在排名前50？涨停是什么方向？ |
| ③ | P1候选触发 | 深析 | op_multi_snapshot + op_stock_minute | 三维确认齐？买点窗口打开？ |
| ④ | 涨停板异动 | 深析 | op_limit_list | 新增涨停/炸板归因 |
| ⑤ | 大盘趋势 | 深析 | op_index | 量能/趋势是否支持操作 |
| ⑥ | 盘中新方向 | 深析 | op_sector_rank + 跨板块归因 | 盘前未覆盖方向走强 → 三维评估 |

- 快扫每分钟固定检查①②
- 深析按信号触发③④⑤⑥
- 三维齐但不买 = 必须在模拟看盘日志写明放弃理由（未记录=过程违规）

## 五、决策落盘要求

### 5.1 买/卖前必须写思考链路

每一笔买/卖在执行前必须先写 `HHMM_<动作>_<标的>_思考链路.md`：

```
- 触发时刻 HH:MM
- 三维确认：资金（涨停股名+时间）/ 预期依据（催化锚）/ 价格（具体价位）
- 买前三件事：预期 / 兑现标志 / 失效标志
- 备选方案：考虑过哪些标的，为什么放弃
- 仓位与价位：买卖数量、价格
- 退出条件：兑现/失效标志
```

未写思考链路 → 不允许动账户。

### 5.2 三维齐但不买

必须在模拟看盘日志写★决策记录：
- 三维确认评估（各引用具体数据）
- 买入窗口状态（是否打开）
- 最终决策 + 放弃理由
- 未写入 = 过程违规

### 5.3 执行链

**买点触发**：
① 写思考链路.md → ② 检查硬拒绝 → ③ 执行交易+更新state.md+trades.md → ④ 模拟看盘日志追加 → ⑤ 通知用户

**卖点触发**：
① 写思考链路.md（含卖出原因）→ ② 执行交易+更新state.md+trades.md → ③ 模拟看盘日志追加 → ④ 通知用户

**系统硬拒绝场景**（规则直接裁决，零用户介入）：
- 买前三件事任一无法明确 → 不买
- 单股仓位破30% → 不买
- 当日累计亏损>5% → 冷静期，禁开新仓
- 盘前预案外新方向三道关通过 → 直接执行

## 七、收盘评估与复盘

### 7.1 预期对照

- 预期确认/兑现/失效了吗？对照盘前判断 vs 实际
- 盘中感知准确度：哪些信号提前预示了预期变化？
- 覆盖诊断：今天有没有在加速期才发现某个方向？→ 追问为什么盘前没扫到

### 7.2 复盘交易

每笔交易回顾：预期是什么？确认/兑现/失效了吗？决策合规吗？

### 7.3 更新预期阶段

核心框架.md §3.1，标注各方向阶段变化

### 7.4 更新state.md §一§二

虚拟账户：持仓+现金+总资产

### 7.5 合规检查

- [ ] 每笔交易是否对照了三维确认？
- [ ] 买入前是否锁定了三件事？
- [ ] 卖出是否基于预期逻辑而非价格？
- [ ] 是否遗漏了盘中感知的新方向？
- [ ] 复盘标准：赚钱违规=错误 / 亏钱合规=正确
- [ ] 三维齐→必须执行？
- [ ] 买卖决策是否写了思考链路文件？

## 八、输出

写入 `data/daily/YYYY-MM/DD-模拟看盘.md`，内容包括：
- 分钟级持续模拟日志（有信号的分钟才记录，无信号的不写）
- 买卖决策明细（引用思考链路文件）
- 持仓+账户更新
- 复盘与合规检查
- 覆盖诊断结论

思考链路文件写入 `data/daily/YYYY-MM/HHMM_动作_标的_思考链路.md`。
