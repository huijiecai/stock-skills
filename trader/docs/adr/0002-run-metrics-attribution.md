# ADR-0002: 封场 metrics 按 run_id 归因本场

- 状态:已接受
- 日期:2026-08-21(run 336 事故日)
- 相关代码:`trader/core/valuation.py::compute_metrics`

## 背景

live/paper 模式写跨日复用的共享组合(一个组合跑很多场),回放模式一场一组合。
封场时算"本场收益"若直接取组合整体盈亏,共享组合会把历史场次的盈亏算进本场。
run 336 事故:首场只买 1 笔,封场 metrics 却显示整本 -1.39%(含历史持仓浮亏),
本场表现被完全淹没。

## 决定

`compute_metrics` 收到 run_id 时**只归因本场成交**(fills 按 run_id 过滤):

- 本场盈亏 = 本场卖出的已实现(认组合均价成本,继承老底也算)
  + 本场净买入期末仍持有的浮盈(期末价 − 本场成交均价)
- 期初资产 = 期末资产 − 本场盈亏(单一组合时恰等于钱包初始资金)
- run_id=None 时归因整本组合(回放一场一组合,过滤后与整组合同义)
- 期末估值行情:live 场用实时价,回放用当日收盘;取不到浮盈记 0、资产退成本

## 后果

- 正:每场 metrics 只回答"这一场干得怎么样",跨场不互相污染;回放语义不变。
- 负:成本口径是组合均价(而非本场独立成本),继承老底的卖出按组合均价认盈
  亏——有意为之,组合成本是唯一真实成本。
- 约束:fills.run_id 归因字段成为硬依赖,写入侧(engine/工具)必须场场带 run_id。
