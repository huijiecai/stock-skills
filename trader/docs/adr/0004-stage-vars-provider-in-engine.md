# ADR-0004: 阶段变量提供器内置 engine,运行时与契约同源

- 状态:已接受
- 日期:2026-08-19(早期设计讨论定案,原始"附录 14"记录未归档,以本文为准)
- 相关代码:`trader/core/engine.py::prev_trading_day/_derive_date_vars/_stage_vars/stage_var_schema`

## 背景

阶段 prompt 的占位符变量(date/prev/weekday/gap/rounds/now/clock/topic…)谁来提供?
选项:①每个系统自己写提供器插件;②平台 engine 内置一套通用提供器;③发起方
(CLI/API)全量传入。系统自写插件灵活但每家重复造轮子且口径必漂移;全量外传则
把推算逻辑(上一交易日跳过节假日等)推给所有调用方。

## 决定

engine 内置通用变量提供器(原"附录 14 已定"):派生变量由 engine 统一推算,
调用方只传业务变量(date/topic 等)。**运行时注入与编辑器变量契约必须同源**——
`stage_var_schema`(编辑器变量面板/占位符 lint/替换预览)与 `_stage_vars`(运行时
注入)共享同一套推导规则,预览即所得。

## 后果

- 正:所有系统的日期口径一致(如"上一交易日"只有一个算法);新系统零变量代码。
- 负:系统级自定义变量无插件口——目前无此需求;真出现时在 engine 加提供器分支,
  而不是开插件机制。
- 约束:`prev_trading_day` 依赖行情数据探测节假日,离线环境不可用;
  ADR-0003 的"派生变量不依赖声明"建立在本提供器之上。
