## 0. 一句话

**平台从"单人自用"升级为"多租户":人(身份)→ 账本(钱)→ 系统(方法)→ 场次(实验)
四层各归其位;账号体系采用业界通用三层形状(Dify 同构);控制面暂用 Python(API-first),
Go 是预留选项而非当前工程。**

## 3. 领域模型(四层)

```
User(人)
 ├── 登录体系(§3.1 三层形状)
 ├── display_name(昵称,可空;公开场合用它不用邮箱)
 ├── 知识(预期文档/自选组)──挂 user,跟着人走
 ├── System(交易系统)──挂 user;远期 visibility(private/shared/市场)+定价 → 只留字段
 └── Ledger(账本 = 持久化 bag,可开多个)
      ├── live 实盘账本(内测仅 user 0 可建)
      └── paper 模拟账本(常驻,给"实时模拟"用)
 Run(场次 = 一次性实验袋,从任意账本 fork:fresh/fork/fork-as-of/custom,跑完封存)
```

口诀:**人管身份,账本管钱,系统管方法,场次管实验。**

### 3.1 账号体系(三层,Dify/OpenAI 同构)

| 层 | 表 | 职责 | 演进(全是加行) |
|---|---|---|---|
| ① 登录凭据 | identities(user_id, provider, identifier, credential_hash) | 证明"你是你" | password(邮箱+argon2)→ email_code → github(github_id)→ phone → google |
| ② 会话 | sessions(token_hash, user_id, expires_at, revoked_at) | 登录态,可吊销可续 | M1.5 上线登录端点时启用;CLI `trader login` |
| ③ API Key | api_keys(id, user_id, key_hash, name, revoked_at, last_used_at) | 程序通行证(sk- 前缀,可命名/吊销/计量) | 计量与将来计费挂这;订阅模式天然复用 |

同一 user 可挂多种身份(邮箱注册的老用户点 GitHub 登录→绑定同一人)。
参考实现:Dify(GitHub: langgenius/dify,自托管 `docker compose up -d` 可体验全流程;
注意其开源协议禁止多租户 SaaS 商用——**只学不抄底座**)。

## 6. 规模墙备忘

按撞上先后:**LLM 速率与成本 → astock/TDX 服务化 → 运维形态(单机→池→k8s)→ PG 容量**。
无一堵是 Python 语言本身;Python worker 真实劣势是工程重量(单进程 100-150MB vs Go 10-30MB),
千级会话后才转化为迁 Go 的工程理由(§5 触发器)。

## 附录 A:讨论记录(8/19)

1. **多用户就绪评估**:模拟验证当天可用;卡在 正本袋唯一/知识共享/命名空间 三处硬碰撞
   +调度/成本两处运营缺口 → 引出本改造
2. **架构之争**:用户提议 Go 领域后端(Python 专注 agent 执行);分析后结论——该拆法
   (模式 B)成立,但负载画像(会话=分钟级 LLM I/O 等待,并发=会话数)决定语言非瓶颈;
   分档:~100 用户需 worker 池 → ~2k 需 API 多副本+astock 服务化 → ~10k k8s,语言仍非死因。
   最终用户拍板:Python 先行(D1-D3),Go 留作演进选项(§5 触发器写死)
3. **业界模式调研**:A=全 Python 分角色进程(Dify/LangGraph);B=Go 控制面+Python 执行
   (B 端常见,用户原提议);C=客户端 agent(Anthropic 式,不适用——会话需 7×24 服务端)
4. **账号/账本模型**:用户明确 登录账号 vs 交易账本 必须分离;账本=持久 bag 的泛化统一了
   原"正本袋改造"问题
5. **认证形状**:讨论从"内测直发 token+环境变量"升级为业界三层(identities/sessions/
   api_keys,Dify/OpenAI 同构);邮箱验证码登录因依赖邮件送达放公测(D8);Google 仅海外
6. **Dify 调研**:开源(langgenius/dify),后端核心纯 Python(Flask+Celery),自托管可体验;
   license 禁止多租户 SaaS 商用——学架构不抄底座
