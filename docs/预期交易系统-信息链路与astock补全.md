# 预期交易系统：信息链路与 astock 补全路线

> 状态：astock 实时原始行情能力已基本收口，下一阶段转向 trader/Brain 消费链路  
> 目标：从第一性原理定义预期交易所需的信息和决策链路，明确 astock、trader、Brain 与 Web 信息源的责任边界。  
> 边界：astock 负责可观察的市场事实与确定性派生指标；trader 负责预期、证据、状态、账户和执行约束；Brain 负责归因、预期差判断与交易决策。

---

## 一、结论

旧交易系统的方向正确，但目前更接近“资金确认后的强势交易系统”，还不是完整的“预期差交易系统”。

它比较擅长回答：

- 哪个方向正在走强？
- 是否有具体催化？
- 直接受益股是否联动？
- 龙头是谁？
- 资金确认是否还在？

但还没有完整回答：

- 消息出现前，市场原来预期什么？
- 新信息改变了哪一个未来变量？
- 这个变化超出市场预期多少？
- 当前价格已经交易了多少？
- 剩余预期差是否还值得承担风险？

因此，现有系统对“确认后买入”的描述相对清楚，但对“预期兑现”和“预期失效”的区分仍不稳定，容易在实践中退化成主观止盈或事后归因。

---

## 二、第一性原理

### 2.1 重新定义预期

预期不应定义为“市场资金正在投票的产业方向或事件催化”。资金投票是确认，不是预期本身。

更准确的定义是：

> **预期 = 市场对未来某个关键变量的当前判断。**  
> **预期差 = 新证据所指向的未来结果，与市场原有判断之间的差。**

关键变量可以是价格、销量、订单、产能、成本、毛利、利润、政策约束、资本开支或事件结果。

一笔交易的机会可以抽象为：

```text
新信息带来的预期变化
× 公司对关键变量的受益弹性
× 尚未被价格反映的比例
× 资金继续传播该预期的可能性
- 判断错误与交易失败的损失
```

### 2.2 六个必须分开的概念

| 概念 | 含义 |
|---|---|
| 催化 | 新发生的事实、公告、数据、政策或事件 |
| 原有预期 | 催化出现前，市场认为未来会发生什么 |
| 新预期 | 新证据把未来判断改变成什么 |
| 预期差 | 新预期相对原有预期的增量 |
| 资金确认 | 市场是否开始相信并交易这个变化 |
| 定价完成 | 预期差是否已经大部分进入价格 |

资金确认只能证明“市场开始相信”，不能证明“当前价格仍有足够空间”。因此，三维确认应是买入的必要条件，而“剩余预期差与收益风险比”必须成为额外门槛。

## 三、完整决策链路

```text
市场先验
→ 新增事实
→ 预期发生变化
→ 建立可证伪的因果假设
→ 建立直接受益池和竞争性解释
→ 观察市场是否确认
→ 判断剩余预期差
→ 选择交易表达和买点
→ 持续跟踪逻辑、定价和资金确认
→ 兑现、失效或交易确认失败时退出
```

### 3.1 盘前：建立可交易假设

1. **建立市场先验**：此前市场预期什么，股价此前涨过多少，当前处于低预期、正常预期还是高预期。
2. **获取增量信息**：公告、产业数据、政策、外盘映射、公司行为和异常资金行为。
3. **提出可证伪假设**：明确哪个未来变量改变，而不是只写“AI”“半导体”等标签。
4. **建立最短传导链**：事件 → 产品/需求 → 经营变量 → 公司。
5. **建立固定池**：区分直接受益、销量受益、相邻题材、成本受压和研究样本；池必须先于行情验证建立。
6. **保留竞争性解释**：同一异动可能由多个事件驱动，不能只保留最顺手的故事。
7. **锁定预期契约**：确认、兑现、失效条件，观察指标、时间窗口和有效期限。
8. **制定场景预案**：把可能的盘中状态写成可观察的 if-then 条件，而不是写“重点关注”。

### 3.2 盘中：验证而不是临时编故事

1. 读取市场状态，先判断当前赚钱效应、亏钱效应和风险偏好。
2. 检测相对上一轮发生的变化，而不只读取当前静态排名。
3. 发现异动后，搜索具体事件并提出一个或多个归因假设。
4. 根据因果链建立或读取固定池，再用行情验证联动。
5. 在归因成立的固定池中比较首次发动时间、涨速、成交主动性和持续性，确认领导标的。
6. 检查预期依据、资金广度和领导价格响应是否同时成立。
7. 判断当前上涨是否仍有未定价空间，还是已经进入一致加速或兑现阶段。
8. 通过买点、收益风险比、账户排序和硬约束后执行。

### 3.3 持仓：同时跟踪三条状态

| 状态线 | 核心问题 | 典型证据 |
|---|---|---|
| 逻辑状态 | 预期依据是否加强、不变或被证伪？ | 公告、产业数据、事件进展、传导链变化 |
| 定价状态 | 还有多少预期差没有进入价格？ | 催化落地后的价格响应、此前涨幅、好消息是否还能推动价格 |
| 交易状态 | 市场是否仍在确认本次交易？ | 固定池广度、领导主动性、相对强度、承接、成交方向 |

动作矩阵：

| 逻辑状态 | 定价状态 | 资金状态 | 动作 |
|---|---|---|---|
| 加强 | 尚未充分定价 | 开始确认 | 买入或在独立买点加仓 |
| 不变 | 尚未充分定价 | 持续确认 | 持有 |
| 不变 | 已充分定价 | 仍然强势 | 兑现，不等待明显转弱 |
| 不变 | 尚未兑现 | 确认消失 | 退出交易，预期保留观察 |
| 被证伪 | 任意 | 任意 | 清仓 |
| 不清楚 | 不清楚 | 不清楚 | 不操作 |

### 3.4 三类退出必须互斥且可解释

1. **预期失效**：核心事实被否定、传导链断裂或直接受益关系不成立，清仓。
2. **预期兑现**：事件或数据已经落地，预期差大部分进入价格，剩余上涨空间低于风险，减仓或清仓。
3. **交易确认失败**：产业判断可能仍成立，但市场不再确认本次交易，退出持仓并保留预期观察。

单纯“涨了 X%”不是兑现。价格阈值只有在买前被定义为定价完成的可解释代理，并与池广度、催化进度、市场响应共同验证时，才能进入兑现条件。

## 五、真实看盘所需信息

### 5.1 市场正在奖励什么、惩罚什么

真实看盘首先需要理解市场的定价偏好，而不是只看哪个板块涨幅第一。

| 维度 | 必需信息 |
|---|---|
| 市场广度 | 沪深北上涨、下跌家数，以及完整个股排行和涨跌停状态 |
| 量能 | 全市场和各板块累计成交额；历史同期比较按需读取历史分钟线 |
| 涨停生态 | 当前完整涨停/跌停清单、是否封板、五档封单；不要求精确炸板事件流 |
| 接力效果 | `昨日涨停(880863)`、`昨日连板(880812)`、`昨日断板(880963)`风格板块及成员的当日反馈 |
| 亏钱效果 | 跌幅榜、跌停列表、昨日强势样本反馈，以及个股分钟价格路径 |
| 风格 | 大盘/小盘、成长/价值、主板/双创的相对强弱 |
| 板块状态 | 成员覆盖、涨跌平、中位涨幅、涨跌停、成交额和最近几轮变化 |
| 资金迁移 | 新方向扩散、旧方向缩容、方向之间的吸血关系 |

### 5.2 单个预期如何被确认

| 维度 | 必需信息 |
|---|---|
| 固定池广度 | 上涨、下跌、强涨、涨停、可交易成员数量和覆盖率 |
| 领导关系 | 分钟级启动时间、相对涨速、成交持续性和带动顺序；分笔只在少量标的深析时按需查看 |
| 价格路径 | 开盘、回撤、修复、突破、十分钟变化和距高点回撤 |
| 相对强度 | 个股相对固定池、板块相对指数、方向相对全市场 |
| 状态变化 | 相对上一轮是扩大、稳定、缩容还是反转 |
| 催化更新 | 盘中是否出现新的支持证据、反证或事件落地 |
| 定价判断 | 好消息是否仍能推动价格，还是出现利好钝化和分歧扩大 |

### 6.3 关于“每轮已经有分钟信息”的澄清

当前 `trader context capture` 每轮自动获取的是：

- 持仓、固定池和计划代码的实时 quote；
- 主板异动候选和成交额榜；
- 板块排名；
- 六个指数。

实时 `PricePath` 由当下 quote 的开、高、低、现价派生，`bar_count=0`，没有十分钟变化。原始数据并不缺失：`astock live minute` 和 `astock live tick` 已存在；缺的是 trader 对候选、持仓和领导标的的按需消费。

正确方案不是每轮拉取全市场分钟线，而是：

```text
全市场用轻量快照发现状态变化
→ 对持仓、固定池、异动候选按需取分钟线
→ 对少量领导候选按需取分笔成交
```

## 七、能力状态与处理结论

状态含义：**已覆盖**表示 astock 已能提供原始事实；**派生**表示不新增行情接口，由 trader/Brain 使用现有数据计算；**待保障/数据未就绪**表示接口已有但当前覆盖不足；**可选已有**表示原始数据可按需读取但不是默认链路；**不做**表示不符合投资者级预期交易的必要性。

| 编号 | 能力 | 状态 | 处理结论 |
|---|---|---|---|
| P0-1 | 实时全市场广度 | 已覆盖 | `live index` 提供沪深北上涨/下跌家数；排行和涨跌停由 `live market` 补充，不再建设一个返回所有市场信息的总命令 |

### 明确不建设的能力

- 不建设需要 Token 的 Level-2 全量委托、撤单和队列系统。

- 不新增把全部行情重新包装到一个命令中的聚合接口。
