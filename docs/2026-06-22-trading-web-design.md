# AI 交易系统平台 — 产品设计

> 状态：草案 v0.3
> 目的：理清楚产品是什么、场是什么，不涉及实现

---

## 一、产品定位

**一句话：让不会编程的交易者，拥有自己的 AI 交易系统。**

类比：QuantConnect 让人写 Python 做量化。我们让人写 SKILL（自然语言/Markdown）做交易。AI 读懂 SKILL 后自主执行，用户通过 Web 管理一切。

### 三大支柱

| 支柱 | 解决什么问题 | 现状对标 |
|------|------------|---------|
| **免费行情数据** | 散户每年花几百~几千买数据 | akshare/tushare 付费，TDX 免费 |
| **SKILL 定义策略** | 不会编程也能设计交易系统 | 量化平台必须写 Python |
| **AI 自主执行 + Web 管理** | 人肉盯盘 → AI 替你跑 | 手动交易 or 半自动信号 |

### 目标用户

想有自己交易系统但不会编程的交易者。他们现在：
- 花钱买数据
- 靠人肉盯盘、手动执行纪律
- 想系统化但写不了代码
- 试过量化平台但学不会 Python

---

## 二、用户旅程

```
选数据 → 写SKILL → AI跑起来 → Web管结果
```

1. **选数据**：平台提供什么数据，用户选哪些来支撑自己的策略
2. **写SKILL**：用自然语言定义交易规则（什么条件买、什么条件卖、仓位怎么管）
3. **AI跑起来**：AI 读懂 SKILL，每天自动盘前分析→盘中执行→盘后归档
4. **Web管结果**：看 AI 做了什么、赚了多少、为什么这么操作

## 三、场（Scenes）

### 第一层：数据（免费行情）

用户策略的"原料"。平台通过 TDX 免费直连提供。

#### 场 1：行情总览

**一句话**：市场全貌。

- 三大指数（上证/深证/创业板/科创50）+ 分时图
- 涨跌家数、成交额、量能对比
- 涨停/跌停/炸板计数
- 外围市场：美股昨夜收盘、港股实时
- 市场温度计

#### 场 2：板块

**一句话**：钱往哪个方向去了。

- 板块涨幅榜（行业 + 概念，可切换）
- 每个板块：涨幅、涨停数、领涨股、成交额
- 板块轮动视图：今天 vs 昨天 vs 本周
- 涨停归因：涨停股按概念聚类

#### 场 3：个股

**一句话**：一只股票的全貌。

- 实时行情（价格、涨跌幅、成交量、换手率）
- K 线图（日K/周K/月K）
- 分时图 + 盘口
- 所属板块/概念标签
- 近期涨停记录、连板天数
- 基本面摘要（市值、PE、行业）

#### 场 4：涨停天梯

**一句话**：连板生态。

- 连板天梯图：5板/4板/3板/2板/首板
- 炸板率统计
- 涨停归因标签
- 历史对比

#### 场 5：全局搜索

**一句话**：任何页面搜代码/名称/板块 → 直达。

---

### 第二层：策略（SKILL 系统）

用户设计自己交易哲学的地方。这是平台的核心壁垒。

#### 场 6：SKILL 编辑器

**一句话**：用自然语言写你的交易规则。

- SKILL 结构引导：核心理念 → 买卖规则 → 仓位管理 → 风控约束
- 模板起步：提供经典策略模板（趋势跟踪/板块轮动/预期驱动等），用户基于模板修改
- 实时校验：检查规则是否自洽（有没有矛盾、有没有覆盖盲区）
- **用户价值**：不用学 Python，用中文写清楚"什么条件买、什么条件卖"就行

#### 场 7：SKILL 市场

**一句话**：发现和分享别人的交易策略。

- 公开 SKILL 浏览、评分、评论
- 按风格分类：趋势/波段/短线/价值
- 按回测表现排序
- 一键 Fork → 改成自己的版本
- **用户价值**：不会从零设计也没关系，从高手的 SKILL 出发

#### 场 8：回测（模拟验证）

**一句话**：策略上线前先验证。

- 用历史数据跑 SKILL → 产出：收益率、胜率、最大回撤、交易记录
- 不同时间段对比（牛市/熊市/震荡市）
- 与基准（沪深300）对比
- **用户价值**：上线前知道策略靠不靠谱，不用拿真金白银试

---

### 第三层：执行（AI 自主运行）

AI 读懂 SKILL 后，每天自动跑。

#### 场 9：AI 运行状态

**一句话**：AI 现在在干什么。

- 运行模式：盘前分析中 / 盘中监控中 / 盘后归档中 / 休市
- 今日操作摘要：买了几笔、卖了几笔、当前持仓
- 异常告警：数据拉取失败、规则冲突等
- **用户价值**：一眼知道 AI 在正常工作

#### 场 10：AI 账户

**一句话**：AI 真金白银的战绩。

- 当前持仓（代码、名称、仓位%、买入价、现价、浮盈%）
- 账户概况（总资产、现金、持仓市值、累计收益率）
- 资产曲线（逐日，标注买卖时点，对标沪深300）
- 完整交易记录（每笔买卖的价格、盈亏、**AI 的决策理由**）
- 绩效指标（胜率、盈亏比、最大回撤、夏普比率）

#### 场 11：AI 每日报告

**一句话**：AI 每天怎么分析、怎么决策的。

- 盘前分析：催化扫描、方向评估、今日预案
- 盘中记录：异动捕捉、买卖决策链路
- 收盘总结：今日操作、持仓回顾、明日展望
- **用户价值**：不是黑箱给结论，而是展示完整推理过程——用户可以学到方法论

#### 场 12：信号推送

**一句话**：重要事件主动通知。

- 买入/卖出信号：推送（标的、价格、仓位、理由摘要）
- 风控预警：接近止损线、仓位异常
- 信号详情：点击 → 展开完整决策链路 + 跳转个股页

---

### 第四层：管理（Web Dashboard）

用户的管理中心。

#### 场 13：Dashboard（首页）

**一句话**：打开就看到一切。

- AI 运行状态（场9摘要）
- 账户快照（总资产、今日盈亏、持仓概览）
- 今日信号（场12摘要）
- 快捷入口：SKILL 编辑器、AI 报告、自选股

#### 场 14：自选股

**一句话**：我关注的股票。

- 自选分组（可多组）
- 实时行情列表
- 提醒（涨跌幅阈值、涨停、放量异动）

#### 场 15：我的账户

**一句话**：用户自己的真实持仓记录（如果用户自己也交易）。

- 手动录入持仓和交易
- 资产曲线和绩效分析
- 与 AI 账户的对比

## 四、场之间的关系

```
用户打开平台 → 场13 Dashboard
    │
    ├── 管数据 → 场1行情 → 场2板块 → 场4天梯 → 场3个股
    │                                              ↑
    │                                    场5 全局搜索（任何页面可用）
    │
    ├── 写策略 → 场6 SKILL编辑器 → 场8 回测 → 场7 SKILL市场
    │
    ├── 看AI跑 → 场9 运行状态 → 场10 AI账户 → 场11 每日报告
    │                                    ↑
    │                         场12 信号推送（主动触达）
    │
    └── 管自己 → 场14 自选股 → 场15 我的账户
```

## 五、MVP 优先级

| 优先级 | 场 | 理由 |
|--------|---|------|
| **P0（必须有）** | 13 Dashboard + 10 AI账户 + 11 每日报告 + 12 信号 | 你自己现在就需要这些 |
| **P0（必须有）** | 1-4 行情数据 | 免费数据是用户来的理由 |
| **P1（第二批）** | 6 SKILL编辑器 + 8 回测 | 核心差异化，但需要时间打磨 |
| **P2（第三批）** | 7 SKILL市场 + 14 自选 + 15 我的账户 | 有用户了再做 |

## 六、开放问题

1. **SKILL 的技术形态**：SKILL 现在是 Markdown 文件给 AI 读的。Web 上的 SKILL 编辑器要做什么程度？纯文本编辑 + 预览？还是可视化拖拽规则？
2. **数据 API 化**：astock 目前是 CLI。Web 需要 HTTP API。是 astock 加 HTTP 层，还是独立数据服务？
3. **执行接口**：AI 目前是模拟交易（虚拟账户）。未来要不要接真实券商接口？这是完全不同的产品形态。
4. **回测引擎**：回测需要历史数据 + 模拟撮合。astock 有历史数据，但没有撮合引擎。怎么做？
5. **多用户隔离**：每个用户有自己的 SKILL + AI 实例 + 账户。架构上怎么隔离？
6. **SKILL 的"可执行性"边界**：用户的 SKILL 写到什么程度 AI 才能执行？"低买高卖"太模糊，"突破20日均线买入10%仓位"才可执行。SKILL 编辑器怎么引导用户写出可执行的规则？
